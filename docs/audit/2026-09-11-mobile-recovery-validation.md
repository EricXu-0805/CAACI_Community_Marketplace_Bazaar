# 手机图片、前后台恢复与轮播补测

起始版本：`0bb98ef63f98926d7de99c8e75358e5b983febf9`。开始时本地、main 和正式站点清单一致。
本轮继续验证上一轮未覆盖的路径；最终提交、CI 和部署回执保存在本地 `output/playwright/mobile-validation-20260911/RELEASE_RECEIPT.md`。

## 新发现与修复

广场轮播只给当前链接设置 `tabindex=0`，隐藏链接则省略属性。应用的通用按钮键盘适配随后把缺失属性补成了0，因此键盘可以依次聚焦到两张不可见的广告。

WebKit 实际复现：三张轮播中的第三张可见时，Tab 依然先进入第一、第二张隐藏链接。修复后隐藏链接显式设为 `-1`，Tab 只进入当前可见链接，然后进入暂停按钮；Home/End 切换和 Enter 打开链接通过。

旧轮播暂停测试会在数据库没有多张轮播时跳过，而且只检查按钮状态。本轮改用隔离的三张轮播夹具，验证实际自动切换、触屏暂停超过一个周期、移开指针仍暂停、恢复后继续切换，并新增键盘遍历回归。

推送后的正式站点复核又发现商品详情存在同类遗漏：Tab从第一张可见图片进入第二张隐藏图片，之后才到返回按钮。商品图片按钮同样补上显式的当前0、隐藏-1，并扩展原有图片导航回归，覆盖Mac两种尺寸、iPad横竖屏和360/390px手机的实际Tab路径。以随后包含此修复的最终提交作为本轮发布结果，首次推送不算最终验收。

进一步查看iPad截图发现，仅限制隐藏图片焦点仍不够：在切换动画中立刻Tab到新图片，浏览器会滚动内部`overflow:hidden`容器。正式站点出现计数1/2但第二张图片可见，内部横向滚动506px；本地新增真实位置断言复现580px错位并失败。商品与广场轮播的H5外层和内部wrapper改用`overflow:clip`，保持轮播依靠变换切图，阻止额外的焦点滚动。隐藏链接继续保持tabindex=-1。这一选择依据[MDN的overflow说明](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/overflow)，并由浏览器检查实际图片位置验证；小程序不应用该H5样式。

完整回归随后捕获聊天恢复的时序缺陷：消息列表已经显示，但报价/约见初始化尚未完成时，前台监听还没有注册，快速返回会漏掉商品状态刷新。原先通过过的前台测试在该时序下失败，随后通过挂起报价请求稳定复现“消息已更新、已售出状态仍缺失”。把监听安装移到这些异步快照之前，保留现有的会话身份检查、可见性检查与卸载清理；延迟加载场景成为固定回归，不以延长等待掩盖问题。

## 测试中的校正与限制

- 草稿恢复的第一次读取发生在页面更新之前，瞬时值为空；后续加入等待，再检查实际恢复的标题与价格，通过。没有把这次过早读取算成产品缺陷。
- WebKit网络记录没有提供完整附件字节，初次从multipart提取的“magic”落到了边界文本上；后续fetch探针也未捕获已绑定的客户端fetch。以上探针不构成JPEG二进制验证。本轮确认的是浏览器发布成功、上传声明格式和写入次数。
- 控制台的`interactive-widget`提示是该WebKit忽略一个视口参数；本轮未新增应用运行异常。
- HEIC是合成格式文件，失败是主动注入的解码错误，不等于实测所有iPhone照片或所有浏览器解码器。
- 前后台切换使用页面生命周期事件，不等于iOS系统冻结/杀进程后恢复。
- 本机只有Apple命令行开发工具，没有完整Xcode、iOS Simulator或可控制的实体iPhone/iPad。真实输入法、系统照片选择器、Safari工具栏和系统挂起仍需真机验收。
- 本轮没有进行生产高并发压测，不能据此给出容量承诺。
