# 商品封面与保存期间编辑验证 · 2026-09-11

本轮从用户实际操作发布、编辑商品的路径补查，起始代码、远端 main 和生产清单均为 `fd2c0892b6ab12c7a38a3439e8f21827429e8a21`。确认并修复两类问题：新照片设为封面后保存顺序错误，以及上传期间仍可修改表单导致提交内容与屏幕内容不一致。

## 发现与修复

1. **新封面保存后变回旧照片。** 在 WebKit iPhone 13 模拟浏览器打开合成商品，添加本地图片，点击“设为封面”。预览正确，但保存请求仍按“所有旧图片、所有新图片”排序。修复为在原有位置替换上传成功的照片，并保持图片尺寸与图片逐一对应。上传结果记录原始索引，前一张上传失败时不会将后一张错误放到封面位置。同一处理同时用于编辑和新发布草稿的补图重试。
2. **保存过程中还可改价格、删图或切换分类。** 价格先读取，而部分文字和分类在图片上传后读取；用户在慢网上传期间改动，可能产生混合内容或丢失后续改动。现在上传、保存期间锁定表单输入和修改按钮，忽略此时返回的相册、定位结果。失败后恢复编辑，保留表单和所选照片。uni-app 的 H5 输入禁用会渲染为 `readonly`，浏览器验证检查实际不可编辑，而不是只检查原生 `disabled` 属性。

未改变商品权限、数据库结构、内容审核或账户隔离规则。
