# 聊天报价与约见的慢网恢复验证

起始主分支与生产版本为 `0c119fc78198bfeb425334365004d879db8f43b7`，本轮已重新核对一致。

## 发现与修复

1. 报价请求尚未返回时，关闭后重新填写一份报价，旧请求成功会关闭新面板。浏览器实际复现：提交60美元，重开填写55美元及新备注，旧响应返回后对话框数量变为0；只有第一笔请求发出，新草稿丢失。
2. 报价写入成功后，读取最新报价列表失败，旧界面仍保留原报价表单、显示读取错误并恢复发送按钮，容易诱导重复发送。实际复现记录为：成功写入后503，表单仍打开、发送按钮 `aria-disabled=false`。
3. 报价与约见表单具有相同的生命周期问题。修复按每次打开的表单区分提交归属；在原表单发送期间冻结输入、快捷金额/地点与日期时间选择，仍允许关闭和填写新的草稿。旧响应不能关闭新表单，也不能把焦点从另一个表单移走。
4. 服务端确认发送后先结束所属表单；随后刷新失败时明确提示“已发出，聊天记录将在连接恢复后更新”，由现有同步机制补齐记录。发送本身失败仍保留原值并恢复编辑，用户可明确重试一次。

## 验证设计

新增16条浏览器场景，覆盖390×844手机和820×1180平板尺寸，报价/约见各四条：关闭重开与旋转；关闭后打开另一种表单且保持焦点；发送失败后编辑重试；发送成功但刷新失败、恢复后只显示一条记录。请求与用户数据全部使用本地隔离夹具，不创建生产报价、消息、约见或通知。

约见通过实际H5日期/时间控件选择。WebKit使用触屏点选滚轮，原生控件可用时直接填写；没有修改Vue组件状态或强行派发组件change事件。

初次测试遇到的两个测试层问题已保留原始记录：状态播报与可见提示文案重复导致严格选择器报错；手机WebKit不支持鼠标滚轮。分别改为识别可见提示与触屏点选。开发热更新打断过一轮选择器测试，该轮不作为最终版本证据；最终验证在源码固定后重新执行。
