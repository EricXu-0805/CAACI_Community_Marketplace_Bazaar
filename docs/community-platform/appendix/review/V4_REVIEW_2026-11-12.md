## 诊断

V4 并不短：15 份 Markdown 共 1,578 行，另有 14 份 HTML 镜像、两份哈希相同的 demo 代码和一个 72 文件的 zip。它显得潦草，原因有三。第一，该拍板的地方都没有拍板。主导航、五个板块的中文名、视觉方向、隔离测试库、活动页范围、内容和举报负责人，全写成「建议」「待确认」「后续可增量引入」，没有一处写明由谁在什么时候定。V2 里能直接拿去开会的数字也被删了：求助帖 24 小时真人回复率 70%、D7 留存 25%（至少 40 人）、邀请 30–60 人、60 条审核样例。在 V4 当前文档里搜这些数字，结果为 0，只剩一句「约 5–8 名……不代表统计证明」。第二，文档和代码各说各话。OMO_PROMPT 把「社区、二手、活动、消息、我的」写成既定导航，正式 tabBar 实际是「首页、广场、发布、消息、我的」，也没有任何任务负责改它。五个板块里有三个，方案/原型和 P2 代码用的名字不同。BACKLOG 要求「默认板块」和「功能开关」，代码和合同里都没有。ENGINEERING 写「仅 main 启用 Git 部署」，vercel.json 里是全部关闭。状态文件写「CI 仍在运行」，实际上 005ca9d 的公开巡检已经失败，原因是候选库没有应用 P2 迁移。设计规范一次也没提生产里已有的 App.vue token、Eric 2026-06-12 批准的图标和「集」字印章，所以 OMO 只能拿原型 CSS 当目标。而原型本身有 100 处 8–11px 的小字，次要文字对比度只有 2.3–3.8:1。

第三，对没有聊天上下文的 OMO 来说，「怎么开工」几乎没有可执行的内容。工作站是 Ubuntu 26.04。CI 已经证明 Playwright 1.60 在 26.04 上装不了浏览器；PG17 不在两个硬编码路径里时，32 个数据库测试会静默跳过，照样报通过。V4 对此只写了「需要 Playwright 浏览器依赖」。隔离测试库只写了「本地或隔离」，没有指出仓库里已有 RUNBOOK 指定的 staging-smoke 项目，也没提从 001 开始全链回放的 LOCAL_BOOTSTRAP。下一项任务「只补失败的商品关联」只有一句话，而代码在跳转之前就把已选商品清空了。同一个事实（preview 共用生产库、续接哪个分支、Mac 上的脏目录）在 4–10 个文件里重复，说法还在漂移。「本轮」出现 58 次，「主代理」出现在 4 个文件里，交接之后这些词都没有了指代。V5 要做三件事：按读者拆成 8 个文件，每个事实只放一处；每个待定项编号后交给 Eric；每个任务都写上命令和可判定的完成条件。
