# Illini Market 社区整合与实施方案

版本 3 · Mac 本地执行版 · 2026 年 11 月 12 日

让 UIUC 华人学生与校友在同一个社区完成找信息、交流、买卖和参与活动。以现有 Illini Market 为基础，把广场扩展成论坛，沿用原有账户、商品、私信与举报能力；CAACI 官网提供官方内容，Local Pass 在真实供给与接口就绪后提供独立付费权益。

本轮交付是可评审的产品方案和本地可点击原型。Eric 主导范围与验收，AI 分批实现。站内 AI、模型选型、真实收费和自有票务后置。

## 2 平台结构与用户路径

用户体验形成一个整体，内容和权益分别由对应系统维护。

| 模块 | 负责什么 | 连接方式 |
| --- | --- | --- |
| CAACI 官网 | 官方文章、Weekly、组织介绍、官方活动、会员与捐款 | 社区显示来源、摘要、原文链接、更新时间；实际公开接口确认后再同步 |
| Illini Market 二手 | 商品、价格、交易状态、买卖私信、面交 | 论坛引用同一商品 ID，售出与下架状态从商品读取 |
| Illini Market 社区 | 问答、经验、校友互助、活动讨论、指南 | 复用现有账户和消息；新增标题、板块、标签、关注与内容整理 |
| 活动 | 主办方、时间、地点、报名来源、取消状态 | 每项活动关联一个主要讨论；先支持权威外部报名渠道 |
| Local Pass | 商家权益、商业订阅、核销、取消与退款 | 先保留公开权益介绍；账户关联与资格查询待真实系统就绪 |

**三条首要路径**

1. 新生在社区看安顿经验，打开帖中的商品卡，进入原商品页面联系卖家；商品售出后，帖中卡片同步显示售出。
2. 用户通过活动入口了解内容，进入该活动的讨论，关注后续更新；报名链接与社区关注是两个动作。
3. 校友分享经验或公开机会，学生在主题中提问；双方自愿继续联系，社区不保证内推与录取结果。

手机主导航采用“首页、二手、社区、消息、我的”，活动从首页和社区进入；桌面可增加活动入口。公开信息以便于浏览为原则，发帖和联系使用现有登录体系。校友身份验证方式尚待确定，原型身份均标为示例。

## 5 本轮原型与验收范围

原型使用虚构示例数据，在本机浏览器运行，无真实账号、支付、报名或外发消息。界面顶部明确标记本地演示；审核角色切换仅用于演示流程，不代表真实后台权限。

| 画面 | 应能检查的内容 |
| --- | --- |
| 首页 | 内容类型、搜索、指南与活动入口 |
| 社区列表 | 五板块、最新、待回答、精选、关注 |
| 主题详情 | 正文、评论、保存、举报、商品或活动引用 |
| 发布 | 标题、板块、正文、关联已有商品，必填校验 |
| 商品详情 | 价格、交易状态、原讨论、联系卖家；售出状态同步 |
| 活动详情 | 示例主办方、时间地点、来源、报名说明、唯一讨论入口 |
| 个人资格 | 社区身份、CAACI 会员、Local Pass 分开展示 |
| 审核队列 | 举报原因、上下文、处置和结果回看 |

五条演示流程：主题→商品→演示消息；发布并关联商品；活动→对应讨论；校友机会→提问；举报→队列→处置结果。另检查搜索空结果、手机布局、输入转义和演示数据重置。浏览器验收结果记录在 `VERIFICATION.md`。

此轮原型用于决定产品结构。其 HTML 演示交互不直接替换现有 uni-app 页面；正式接入时复用现有组件、数据模型、权限和回归验证。

## 6 正式实现的数据与接口约定

以下为候选设计，进入正式开发前依据最新迁移与部署状态确定字段及名称。

| 对象 | 候选增量 | 必须保持的行为 |
| --- | --- | --- |
| posts | nullable title、category、post_type；少量标签；精选和解决状态 | 旧动态无标题仍可读；旧链接不失效；作者权限不扩大 |
| post_items | 沿用现表 | 沿用最多 3 件本人商品的限制；关联时校验所有权与 active 状态，后续售出与下架从商品域获取 |
| 主题关注与收藏 | 按用户与主题唯一记录；关注和收藏分开 | 取消后不再通知；不暴露其他用户收藏 |
| 活动 | 来源系统、来源 ID、原文、时间时区、地点、状态、报名链接、discussion_post_id | 活动与面交分开；取消或改期时讨论显示最新状态 |
| 外部内容引用 | source、source_id、canonical_url、更新时间、可见范围和失效状态 | 用来源组合去重；来源失联显示核对时间；失效内容停止推荐 |
| 优惠 | 来源、商家、条件、有效期、公开或付费资格、核验状态 | 未核实和过期内容明确标记；客户端不授予付费资格 |

搜索先覆盖可公开访问的内容，返回帖子、商品、活动的不同类型卡片；后续再索引可验证的优惠。删除、下架、转私密后同步移出搜索结果。私信与 CAACI 会员资料不自动进入全站搜索或 AI 检索。

通知复用站内体系，区分回复、关注主题更新、商品交易和审核结果，处理重复事件和取消关注。跨站关联由用户主动证明两端账户，支持撤销；社区账户、CAACI 会员和商业订阅不互相替代。

## 7 审核与运营如何落地

关键词检查作为一层规则。真实发布还需服务端权限、限流、文字和图片处理、举报、人工复核和申诉。审核未完成时显示待处理，服务失效不得显示审核通过。编辑内容、换图和对象引用变化也要覆盖。

新板块必须区分正常求职信息、商品交流与垃圾推广；不能把原二手广告规则直接当论坛全部规则。准备正常生活讨论、联系方式、真实招聘、中英混合、图片和误判案例，分别记录漏检和误伤。审核员仅获得完成职责所需的访问权限。

Eric 是项目主导，不等于已经接受每日客服与审核值班。AI 可以生成、检查和整理，真实举报、申诉、合作方确认与发布仍需明确负责人。家晨的合作协调角色、官网和 Local Pass 负责人也属于待对方确认的分工。

冷启动先准备真实可用的内容：新生安顿指南、有效商品、校友经验和可核对活动。可先进行小批邀请，再按回复与审核承接能力扩大到 V2 建议的 30–60 人。数量是试点建议，不是现有用户数或必达承诺。

观察每周获得真人回复的求助、有效买卖对话、跨模块行动、满观察窗的 D7 留存和举报处理时间。报名跳转只算跳转，拿到真实来源回执才算报名；点击聊天不当作成交；原型示例不进入真实统计。V2 的 70% 回复率、25% D7、20 人周互动等暂留为讨论目标，待首批基线数据后确定。

## 8 活动与付费平台的关系

社区建设可以先推进。截图中的联合主办和宣传是合作意向，约 1000 张票、约 5000 美元及“各自拉赞助”不能直接变成确定财务安排。场地报价、活动名称、日期、票款分成、外部售票渠道和我方支出上限仍需确认。

初期让活动页承接介绍、讨论和报名来源。未来若做自有售票，单独处理授权、收款、库存、退款、核销与客服。活动获客评估使用归属于平台的净支出和新增留存用户，不把到场人数算作社区活跃用户。

Local Pass 的旧笔记记录过 Eric 确认的月费规划，8 月蓝图另提出年费方案；没有找到后者取代前者的明确确认。本轮原型不实施收费，接入前重新核定当前价格与权益，并确认实际运营主体、商家供给、资格接口、核销及取消流程。CAACI 会费、捐款、商业订阅、赞助和票款分别说明提供方与用途。

8 月生态蓝图中，正文“建议与待批准”和后附任务提示中的“已批准”互相矛盾。本方案将其中架构、价格、外包与 90 天排期作为历史提案，不继承成已批准安排。11 月相关资助申请不等于已获批、到账或可用于本项目的预算。
