# OMO 接手启动提示

以下正文可直接复制给另一台虚拟机上的 OMO；文件路径均相对交接包根目录，不能依赖原 Mac 路径或登录状态。

---

请接续 Illini Market 社区整合项目，完成当前未结束的小批次，再按依赖推进。不要从头重做研究、原型或已经写好的正式代码，也不要只给我一份新计划。

项目沿用现有 Illini Market，服务 UIUC 华人学生与校友，连接二手、讨论、CAACI 官网内容与活动；商业权益、站内 AI 和自有票务按后续独立批次处理。界面保持清楚、精美、自然的中文，主导航是“社区、二手、活动、消息、我的”。我是 Eric，已授权研究、演示迭代和有权限工程中的独立正式开发小批次。

## 先恢复准确状态

1. 找到交接包。仓库中通常位于 `docs/community-platform/`；如果我提供的是压缩包，就以包含 `PLAN.md`、`handoff/`、`research/`、`prototype/`、`release/` 的目录为根。
2. 先完整读取 `handoff/START_HERE.md` 和 `release/CURRENT_STATUS.md`，记下 `next_task_id`、当前仓库、已有分支、提交、PR、演示地址、已通过检查、未完成验收和环境限制。
3. 依入口阅读当前 `PLAN.md`、背景、设计规范、工程基线、接口合同、迭代清单与虚拟机手册；研究报告用于理解设计取舍。P0–P8 的唯一执行清单是 `handoff/ITERATION_BACKLOG.md`，R01–R10 只是研究建议映射，旧 T 编号和 `revisions/v3` 不是当前任务表。
4. 若状态文件未随包提供，先查同一交接记录指向的远端分支；仍找不到时，只提出缺失的具体入口或版本问题。不要猜测当前分支、宣布阶段完成，或直接从 main 重做 P2。可以继续不依赖该信息的材料阅读和本机环境检查。

## 接续已有工作，不另起一遍

私有仓库为 `https://github.com/EricXu-0805/CAACI_Community_Marketplace_Bazaar.git`。用 VM 自己的 GitHub 权限读取和更新。

先检查当前工作目录的分支、提交与未提交改动，再 fetch 并核对状态文件记录的远端分支。**优先检出或跟踪已有交接分支，保留其已完成代码和提交。** 新目录没有本地分支时，建立对应远端分支的本地跟踪分支；不要因为手册示例写着从 main 新建，就丢掉已有 P2。只有确认没有应续接的分支，或已进入明确的新批次，才按当前规范选择新分支。遇到未提交工作先辨认归属，不 reset、clean、强推或覆盖。

将 `next_task_id` 对应的验收要求与实际代码、提交和检查结果逐项对照，继续缺口。如果文件、代码与状态记录冲突，查具体版本和证据，追加更正；不要仅因文档写“候选”就重复造已有字段，也不要仅因已有代码就认定功能可用。

P1 的隔离环境、账号切换检查和 P2 的数据库、权限、真实浏览器流程可能仍有未完成部分。**记录了未测范围不等于通过验收。** 可在隔离环境尚未就绪时继续不依赖它的离线代码与测试，但 P1/P2 的未满足条件保持未完成；不据此进入真实内测或宣称生产上线。

## 本轮怎样执行

先简短说明“续接哪个任务、哪些已有结果保留、这批补什么、用什么证据验收”，随后直接行动。按锁文件和当前工程说明准备环境，不顺手换技术栈或升级全部依赖。只补当前批次所需代码、迁移和文档；可独立的只读审查或不同文件工作可以并行。

沿用现有账户、商品、广场、私信、举报与通知。P2 聚焦标题、板块和发布→列表→详情，兼容旧动态及本人商品关联，处理部分成功、重复提交与结果未知。主题类型、商业资格和跨站身份不能因研究报告提到就全部塞入 P2。具体字段与当前实现以查证后的合同和代码为准。

常规可逆实现、修复、测试、分支提交与审查无需逐项再次询问。缺少必需权限、身份归属或业务事实时，先完成不受影响的工作，再提出具体问题。

## 环境边界

- 静态 `prototype/` 和公共 demo 是示例界面，浏览器本地记录不是生产数据；它们的通过不能替代正式工程的数据库、权限或真实账号验收。
- **CAACI 官网 preview 使用 Stripe test，仍可能共用生产会员数据库和邮件能力；官网本地开发默认也可能连接生产。严禁把这些环境当作隔离测试库。** 写测试前核对实际数据库、Auth、存储、邮件、支付的目标与隔离证据，只用合成账号和数据。
- Illini 与官网使用不同身份空间，不共享会话、密码、管理员资格或服务端秘密；相同邮箱不直接合并账户。官网已有文章、会员及报名代码，不在社区重复造一套后台。
- 不复制 Mac 的 `.env`、令牌、cookie 或完整家目录。不要把缺少测试配置处理成复制生产配置，不解除现有迁移或部署保护。
- 当前开发授权不等于任意写生产用户、会员、报名、支付数据，也不等于给合作方或会员外发消息。正式迁移、合并和生产发布依当时明确的任务范围及工程规则执行。
- 公共 demo 只发布清单中运行必需的静态文件及资产，不能公开整个交接包、聊天截图、内部日志或凭据；更新后验证普通未登录访客能打开。

## 验收与交付

先运行当批直接相关检查；需要时覆盖真实隔离数据库的匿名/A/B/管理员权限、重复请求、断网恢复、换号、删除与旧客户端兼容。再用真实浏览器完成受影响的手机和桌面流程。根据改动运行项目要求的构建与回归，不把 fixture、类型检查、截图或上一提交的 CI 当作新提交的完整验收。

每个结论附版本和环境，区分：已编码、本地静态检查、模拟测试、真实本地数据库、隔离完整联调、CI、预览部署、生产部署与真人试用。没有执行的项目直接列为未测；失败写清原因和下一步。环境缺失时继续可做部分，不用跳过关键检查换取“全部通过”。

完成一个可检查结果后，提交当前批次并提供分支/PR及适用预览，更新 `release/CURRENT_STATUS.md` 的当前事实与 `next_task_id`，追加本批记录，保留历史。记录至少包含：任务 ID、提交 SHA、修改范围、实际命令与结果、环境非秘密标识、未测项、已知问题、回退方式和下一步依赖。涉及范围或合同的新选择同步更新对应文档，不再建立另一套主任务表。

最后用简洁中文告诉我：完成了什么、哪些检查真正通过、什么仍未完成、我可以在哪里查看，以及下一条任务是什么。
