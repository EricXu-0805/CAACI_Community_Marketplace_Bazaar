# 试用阶段运行与升级清单

2026-09-16，针对当前Illini Market。本文是执行方案，不等于所有门槛已通过。

## 当前优先顺序

1. 继续小范围网站试用并补真实内容，记录具体设备/页面/动作/结果。第一轮优先保证发布、消息、登录和内容可见性；动画只是辅助反馈，不能延迟提交或盖住失败。
2. 先完成复杂搜索1万条规模的等价、性能和混合业务验收，再扩大流量。已有候选在托管小规格上10并发仍出现57014；本轮不能靠把超时改长、减少搜索词或提高通过阈值关闭门槛。
3. 小程序保留发布门禁：真实微信体验版和隐私/域名/主体/审核配置齐全之后，才启用新的账号关联。构建可导入与真实设备闭环分开记录。
4. 原生安装包和未来CAACI App身份整合排在网站/微信稳定之后；不为了“统一账号”复制凭据或直接合并数据。

## 定位和信任信息如何继续做

当前“校园取货点”只表示发布者选择了已知地点标签。当前位置来自设备，可能被伪造；不是身份核验或对现场安全、营业时间的保证。学校邮箱认证证明相应邮箱控制权，不是学校背书，也不保证交易结果。

后续可优先补：地点用途说明、公开区域选择、聊天中双方确认具体位置、取消/改约提醒。真实到场核验应作为单独需求，有明确用途、短保存期、人工争议路径；不要为了多一个绿色勾收集证件、持续GPS轨迹或后台位置。未研究完成前不要加“100%安全”或“真人认证”标签。

## 每次准备扩大流量前

| 检查 | 建议动作与通过证据 |
| --- | --- |
| 登录/账号 | 同一用户登录、退出、跨设备、撤销会话；关联错号/越权为零容忍，立即关闭新增关联并保留调查记录 |
| 发布/图片 | 一次提交一次写入；响应丢失能查回；大图/HEIC/取消后重试；预览和保存后图片一致 |
| 搜索 | 数据量、词数、并发/持续时间和匿名/登录角色固定；记录正确结果、57014与p95，目标沿用搜索<2s、列表<1.5s |
| 聊天 | 消息持久化ID唯一，实时漏收能从历史/补拉恢复；未参与者读不到消息或事件 |
| 后台 | listing/media积压与最老任务年龄；失败/重试不丢事件，图片移到私有区后公共地址不可读 |
| 备份 | 最近完成备份时间、独立Storage对象清单和字节；按pre-data/data/post-data恢复，核对约束/RLS/函数/账号/对象可用性 |
| 客服 | 明确谁在值班、从哪里收反馈/举报、如何升级安全事件；本轮未替负责人承诺响应时限 |

建议在上线试点阶段每天人工复核，并由既有监控记录趋势。初期参考触发条件：搜索超时持续出现或p95连续15分钟高于既定目标、普通任务积压超过5分钟、媒体任务进入failed、发布/登录失败突然上升。5分钟/15分钟是建议的运维触发值，不是当前已配置的SLO；调优要依据试点流量。

## 扩容与数据库变更顺序

- 先看慢查询计划、冷热缓存、RLS成本、连接等待与CPU/内存；把短精准/长描述/12词/无结果/常见词分开测试。
- 优化候选必须与现有排序、过滤、分页、隐藏/停用数据边界等价；分别测匿名和登录角色。将本地快的候选直接推到生产不算验收。
- 若需要缓存表、触发器或回填，给出确切迁移、锁行为、回滚与数据库恢复证据，安排维护窗口。此前生产缓存DDL已被自动审批拒绝，本轮未重试或换工具绕过。
- 若查询成本已合理，再在明确预算内比较实例规格；提高资源不替代正确性或安全验证。本轮未开付费实例。
- 后台扩展依赖现有outbox、分批处理、租约、幂等和SKIP LOCKED；先观测积压再增加worker，不能无限并行抢数据库。

## 版本更新和事故处理

发布前保存精确SHA、适用数据库版本、CI与部署回执；同时确认旧客户端在新后端仍能读取。新字段先兼容添加，再部署客户端，最后做经审核的数据回填/旧字段退役。不要重写已经应用的迁移。

可回滚前端部署不代表数据库也能回滚；删除字段或改变身份关联需单独恢复方案。发现跨账号访问或登录错号时先暂停对应入口，再保留最少量的安全事件编号，不在日志放聊天正文、邮箱、绑定码、令牌或精确位置。

本轮还缺：真实实体输入法/相册/后台恢复、微信体验版与审核、正式原生签名、复杂搜索大规模通过、托管生产恢复闭环。历史逻辑恢复和本机哈希核验有价值，但不是完整生产服务RTO/RPO。
